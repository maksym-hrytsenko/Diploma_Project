# Синтезована голосова тест-сесія

Той самий каталог із 113 голосових команд (`tests/voice_test_phrases.md`,
мінус `YES`/`NO` — див. `voice_pipeline_fixes_log.md` §6.5; прибрані з
коду повністю, не лише з цього списку, оскільки не мали жодного правила
в `fusion.json`. `WORK_MODE` — навпаки, повернений в код і в цей список),
начитаний синтезованим голосом macOS (`say`, голос Samantha) замість
живої людини. Мета — прибрати змінність людської вимови/темпу з
вимірювання, щоб можна було чесно порівняти результати з людською сесією
2026-07-17 (яка `WORK_MODE` ще не застала).

## Файли

- `voice_test_synthesized.m4a` — готовий аудіофайл, ~20 хв 19 с.
- `phrase_order.txt` — той самий список фраз у тому самому порядку, що й
  у файлі вище і в чекліст-артефакті для цієї сесії — звірка результату.
- `say_source_script.txt` — вихідний текст з `[[slnc 9000]]`-паузами між
  фразами, з якого `say` згенерував аудіо (для відтворюваності/зміни).
- `parse_tts_session.py` — розбирає `logs/app.log` після сесії й друкує
  результат (тир + затримка) по кожній фразі, позиційно 1:1.

## Чому пауза між фразами — 9 секунд

`IntentModel.silence_timeout_seconds` = 6с. Пауза 9с гарантує, що кожна
сесія (успішна чи ні) встигає закритися — і, якщо невдала, залогувати
`not understood` — ДО того, як прийде wake word наступної фрази. Це усуває
всі три причини, через які людську сесію 2026-07-17 не вдалось розібрати
на 100% автоматично (тихе загублення коротких фраз, дрейф FIFO-зіставлення
— обидва в `voice_pipeline_fixes_log.md` §6.2/§6.1 методики розбору в
`voice_test_session_script.md`). Тут кожна фраза отримує чистий,
однозначно зіставний результат.

## Як провести сесію

```
source venv/bin/activate
python src/main.py --debug-voice
```

Дайте застосунку кілька секунд на старт (модель Vosk/VAD вантажиться),
відкрийте `voice_test_synthesized.m4a` в будь-якому плеєрі й відтворіть
через динаміки (не навушники — мікрофон має почути) при звичайній
гучності розмови. Не торкайтесь застосунку під час відтворення.

## Після сесії

```
python tests/synthesized_voice/parse_tts_session.py logs/app.log
```

Друкує рядок на кожну фразу — звірте номер рядка з тим самим номером у
`phrase_order.txt`. Значення занесіть у чекліст-артефакт для синтезованої
сесії (лінк — окреме повідомлення) і зіставте з результатами людської
сесії 2026-07-17: чи ті самі фрази провалюються, чи проблема була саме у
вимові.
