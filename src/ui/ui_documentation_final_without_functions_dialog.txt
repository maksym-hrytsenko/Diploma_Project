UI DOCUMENTATION
Gesture & Voice Control
Final approved UI specification

NOTE
The Functions Description Dialog is not included in this document because this window will be redesigned separately. Everything else remains based on the final approved versions: Main Control Panel, Bottom Status Panel, Circular Control Wheel, and Floating Status Bar.

============================================================
1. GENERAL STYLE
============================================================

The interface style is a light futuristic AI-control dashboard for a Python desktop application that controls a computer using gestures, voice, camera, microphone, and keyboard input.

The interface must not be dark. The main background is very light grey / almost white. Dark blue and purple are used only as accents: outlines, icons, active states, glow, buttons, and hover effects.

Visual style:
- Light background.
- Soft glass / plastic panels.
- Large rounded corners.
- Thin purple-blue outlines.
- Light neon glow.
- Smooth shadows.
- Clean line-art icons.
- Minimal details.
- No overloaded UI.
- Futuristic AI / gesture-control look.

Main visual reference:
- Rounded white panels.
- Blue-purple gradient ring.
- Circular module selector.
- Big central button with an open hand icon.
- Mode icons around the circle.
- Floating minimal bar with separated icon groups.

Color palette:
- Main background: #F7F8FF or #F4F6FB
- Panel background: #FFFFFF or #F9FAFF
- Inner placeholder background: #EEF1FA
- Main dark blue: #172A5A
- Secondary text: #6D7285
- Main blue accent: #4F7BFF
- Purple accent: #8B3DFF
- Violet glow: #B76CFF
- Disabled grey: #B8BCCB
- Soft error: #FF5A7A

Icon style:
- Line-art only.
- Stroke width: 2.5–3 px.
- Rounded line caps.
- No small unnecessary details.
- Main icon color: blue-purple gradient or purple stroke.
- Disabled icon color: grey.
- Active icon state: purple-blue glow.
- Central system icon: open palm, not a clicking finger.

Window base size:
- Designed size: 1440 × 900 px.
- Minimum acceptable size: 1280 × 720 px.
- The first implementation can use fixed geometry.
- Later the layout can be scaled proportionally.

============================================================

Element name: panel_control_wheel
Position: x = 800, y = 128
Size: width = 590, height = 460
Border radius: 36
Function: Main visual system control and mode selector.

The central button controls the full system ON/OFF state.

7. SYSTEM STATES
============================================================

Main system states:

System OFF:
- Central button has grey or weak purple outline.
- No strong glow.
- Camera / microphone / keyboard modules may remain visually available but processing is stopped.
- Recognition and command execution are disabled.

System ON:
- Central button has blue-purple glow.
- Enabled modules can process input.
- Current mode is active.
- Floating bar icons show active states.

System Error:
- Only the affected module gets a soft red outline.
- Do not turn the whole UI red.
- Show error text only where needed.

Module states:

Camera Active:
- Camera toggle card active.
- Camera icon blue-purple.
- Status chip: Camera: Active.
- Camera preview should show real video if available.

Camera Disabled:
- Camera toggle card grey.
- Camera preview shows placeholder.
- Status chip: Camera: Disabled.

Camera Unavailable:
- Camera toggle card soft red outline.
- Status chip: Camera: Unavailable.
- Camera preview shows placeholder and warning icon.

Microphone Active:
- Microphone toggle card active.
- Microphone icon blue-purple.
- Voice input can listen if system is ON.

Microphone Disabled:
- Microphone toggle card grey.
- Voice input is not active.

Microphone Unavailable:
- Soft red outline on microphone card.
- Optional warning icon.

Keyboard Active:
- Keyboard toggle card active.
- Keyboard icon blue-purple.
- Keyboard shortcuts/global hooks enabled.

Keyboard Disabled:
- Keyboard toggle card grey.
- Keyboard input module disabled.

Keyboard Error:
- Soft red outline on keyboard card.
- Used when global hook or permission fails.

Mode states:

Flip / Mode Active:
- Flip icon on the circular wheel has glow.
- Floating bar Flip icon also has glow.
- Other mode icons remain normal.

Presentation Active:
- Presentation icon has glow.
- Used for slide/pointer actions.

Call Mode Active:
- Call mode icon has glow.
- Used for video call gesture actions.

Cursor Active:
- Cursor icon has glow.
- Used for direct cursor control.

Only one mode should be active at the same time.

9. RECOMMENDATIONS FOR PYSIDE6 IMPLEMENTATION
============================================================

Recommended class structure:

MainWindow
- HeaderPanel
- CameraPreviewPanel
- ControlWheelPanel
- BottomStatusPanel
- FloatingStatusBar

Separate reusable widgets:
- ModuleToggleCard
- ModeCircleButton
- GlassButton
- StatusIcon
- GradientRingWidget

The Functions Description Dialog should be implemented later as a separate window because its design is not final.

------------------------------------------------------------
9.1 Fixed geometry for the first implementation
------------------------------------------------------------

Because the UI has exact approved coordinates, the first version can use fixed geometry:

widget.setGeometry(x, y, width, height)

Later, proportional scaling can be added:

scale_x = current_width / 1440
scale_y = current_height / 900

Then every coordinate can be multiplied by the scale factor.

------------------------------------------------------------
9.2 Styling with QSS
------------------------------------------------------------

Use QSS for:
- panel backgrounds;
- borders;
- border radius;
- hover states;
- active/disabled/error states;
- button shadows if possible.

Use objectName for every important element.

For dynamic state styling, use custom properties:

widget.setProperty("state", "active")
widget.style().unpolish(widget)
widget.style().polish(widget)

Recommended state property values:
- active
- disabled
- unavailable
- error
- standby
- selected

------------------------------------------------------------
9.3 Icons
------------------------------------------------------------

Use SVG icons instead of PNG.

Recommended folder:

assets/icons/
- camera.svg
- microphone.svg
- keyboard.svg
- hand_open.svg
- mode_flip.svg
- presentation.svg
- call_mode.svg
- cursor_click.svg
- info.svg
- settings.svg
- minimize.svg
- close.svg
- expand.svg
- warning.svg

Icons should be editable in color through CSS/SVG or loaded as separate active/disabled versions.

------------------------------------------------------------
9.4 Circular wheel implementation
------------------------------------------------------------

The circular wheel should be a custom QWidget with a paintEvent.

Use QPainter for:
- outer gradient ring;
- soft glow;
- radial separator lines;
- panel background.

Use normal QPushButton or custom buttons as child widgets for:
- central system button;
- four mode buttons.

The outer ring can be drawn with:
- QPainter
- QPen
- QConicalGradient
- QRectF
- drawArc()

------------------------------------------------------------
9.5 Camera preview implementation
------------------------------------------------------------

Do not run the camera loop directly inside the UI thread.

Recommended structure:
- CameraWorker or CameraThread captures frames.
- It emits frame_ready(QImage).
- CameraPreviewPanel receives the signal and updates the displayed frame.

This avoids freezing the GUI.

------------------------------------------------------------
9.6 Floating status bar implementation
------------------------------------------------------------

The floating bar should be a separate frameless always-on-top window.

Recommended flags:
- Qt.FramelessWindowHint
- Qt.WindowStaysOnTopHint
- Qt.Tool

Use:
- WA_TranslucentBackground
- custom rounded background
- fixed size 420 × 64 px

Screen position:
- x = screen_width - 460
- y = 32

Behavior:
- Main window hides when clicking “Minimize”.
- Floating bar appears.
- Clicking the expand button hides the floating bar and shows the main window again.

------------------------------------------------------------
9.7 First implementation order
------------------------------------------------------------

Recommended order:

1. Create MainWindow with fixed size 1440 × 900.
2. Add HeaderPanel.
3. Add CameraPreviewPanel with placeholder.
4. Add ControlWheelPanel with static buttons.
5. Add BottomStatusPanel with 3 toggle cards.
6. Add FloatingStatusBar.
7. Add simple click logic for toggles and modes.
8. Add visual state changes.
9. Later connect real camera/microphone/keyboard modules.
10. Later design and add the final Functions Description Dialog.

============================================================

Approved:
- Light UI style.
- White/light grey background.
- Purple-blue outlines and glow.
- Circular control wheel.
- Central open-palm system button.
