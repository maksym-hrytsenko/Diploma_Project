MULTIMODAL CONTROL SYSTEM -- FUNCTION LIST
What opens/launches what, and what triggers each action.
Full explanations: docs/SYSTEM_FUNCTIONS.md


VOICE -- OPENS AN APPLICATION OR WEBSITE
----------------------------------------
"open browser"    -> opens https://google.com in the default browser
"open chatgpt"     -> opens https://chatgpt.com
"open github"      -> opens https://github.com
"open vscode"      -> launches VS Code
"open terminal"    -> launches Terminal
"open safari"      -> launches Safari
"open chrome"      -> launches Google Chrome
"open spotify"     -> launches Spotify
"open slack"       -> launches Slack
"open discord"     -> launches Discord
"open mail"        -> launches Mail
"open calendar"    -> launches Calendar
"open notes"       -> launches Notes
"open telegram"    -> launches Telegram
"open finder"      -> launches Finder
"open notion"      -> launches Notion
"open photos"      -> launches Photos
"open preview"     -> launches Preview
"open settings"    -> launches System Settings

NOTE: Vosk's speech model does not recognize the words "chatgpt" or
"vscode" -- those two phrases will not be detected no matter how
clearly spoken. Everything else above works.

REMOVED: "open zoom", "open messages", "open whatsapp", "open figma",
"open music" no longer open anything -- dropped from voice, config,
and OSController entirely.


VOICE -- MODES (gesture-scoping, no side effects)
--------------------------------------------------
"presentation mode"  -> enters Presentation mode (or ctrl+shift+p)
"flip mode"           -> enters Flip mode         (or ctrl+shift+f)
"cursor mode"          -> enters Cursor mode       (or ctrl+shift+c)
"call mode"             -> enters Call mode         (or ctrl+shift+w)
"exit mode" (or press ESC) -> leaves whichever mode is active
(Quick Command Circle has no voice/keyboard trigger -- gesture only,
 see GESTURES section below. It doubles as a quick way to pick any of
 the four modes above without remembering its phrase/combo.)

REMOVED: Window Management mode (maximize/minimize/snap-left/snap-
right) no longer exists -- replaced entirely by Call mode. The
ctrl+shift+w combo and "window management mode"/now "call mode" voice
slot were reused as-is rather than reassigned to a new key.


VOICE -- ENVIRONMENTS (opens apps + changes system state)
------------------------------------------------------------
"study mode"
    opens: Safari, Preview
    also:  turns Do Not Disturb ON, resumes/plays Spotify
    on exit: turns Do Not Disturb OFF, pauses Spotify

"movie mode"
    opens: TV (built-in Apple TV app)
    also:  turns Do Not Disturb ON, prevents the screen from sleeping
    on exit: turns Do Not Disturb OFF, allows the screen to sleep again

"news mode"
    opens: News (built-in Apple News app)
    on exit: nothing to undo

Switching directly from one environment to another automatically
undoes the old one first, then applies the new one.


VOICE -- GLOBAL, ALWAYS ACTIVE
---------------------------------
"start"  -> plays/resumes whichever media player currently has focus
"stop"   -> pauses whichever media player currently has focus
            (same underlying system key as "start" -- see limitation below)
"yes" / "no" -> reserved, not wired to anything yet

"next slide" / "previous slide" -> only work while in Presentation mode
    (also: right/left arrow keys, or a closed-fist wrist swipe --
     see GESTURES section below)
"start presentation" -> only works while in Presentation mode --
    sends F5 (PowerPoint/Keynote's own "start slideshow from the
    beginning" shortcut). Entering Presentation mode only arms the
    next/previous-slide mapping above, it does not itself start the
    on-screen slideshow -- this is the command that does.


MODE: CALL (Microsoft Teams) -- "call mode" or ctrl+shift+w
-------------------------------------------------------------
One hand, held up with a given number of extended fingers (thumb doesn't
count toward the total), each held continuously for at least 1.5s before
it fires. Each is a single toggle -- firing it while already in the
target state flips it back rather than no-op'ing. Once a toggle fires,
that same finger count is "locked" until the hand fully leaves the
camera frame and reappears, so it can't accidentally fire twice in a
row.

    ONE_FINGER    -> toggle microphone      (Cmd+Shift+M, Teams' own
                                              shortcut)
    TWO_FINGERS   -> toggle camera          (Cmd+Shift+O, Teams' own
                                              shortcut)
    THREE_FINGERS -> toggle call audio      (mutes/unmutes the Mac's
                                              system-wide output instead
                                              -- Teams exposes no
                                              shortcut for muting just
                                              the call's own incoming
                                              audio)
    FOUR_FINGERS  -> toggle background blur (Cmd+Shift+P, Teams' own
                                              shortcut)

NOTE: MediaPipe's bundled classifier has no "N fingers raised" category,
so the finger count is computed directly from hand-landmark geometry
(distance of each non-thumb fingertip from the wrist), not from the
classifier's own gesture output.


MODE: CURSOR -- "cursor mode" or ctrl+shift+c
------------------------------------------------
The only mode where pointing and pinching touch the real mouse. Now
supports an optional SECOND hand for two extra functions -- one hand
alone still works exactly as before.

One-hand (always available):
    Pointing_Up, held  -> real OS cursor follows the fingertip 1:1,
                           absolute position (camera frame position =
                           same screen position, every frame)
    PINCH (thumb+index touching)
        quick tap-and-release    -> click
        quick tap TWICE in a row -> right-click (instead of two clicks
                                     -- first tap waits ~0.3s to see if
                                     a second follows)
        held and dragged         -> scrolls (natural/drag direction,
                                     distance matches hand movement)

Two-hand (off-hand only matters in Cursor mode):
    Off-hand Closed_Fist, held -> "precision mode": cursor movement is
        scaled to 0.3x of the hand's actual movement, like lowering a
        mouse's DPI, for fine positioning. Releasing the fist snaps
        back to normal 1:1 tracking (the cursor jumps to match the
        finger's current raw position -- an intentional side effect of
        layering a temporary relative "clutch" on top of the otherwise
        always-absolute mapping).
    Off-hand present, NOT fisted (e.g. open palm) + primary hand
    Pointing_Up -> distance between the two hands' index fingertips
        drives zoom continuously: spreading the hands apart zooms IN,
        bringing them together zooms OUT. Sent as repeated
        Cmd+"="/Cmd+"-" presses (same as before), so it works in
        whichever app already supports that shortcut.

REMOVED: Alt+single-hand-pinch zoom no longer exists -- replaced
entirely by the two-hand distance zoom above. No keyboard involved
anymore for zooming in Cursor mode.


GESTURES (general)
---------------------
Pointing_Up (index finger extended), held
    -> outside Cursor mode: shows a laser-pointer dot on screen
       (purely visual, cannot click or interact with anything)
    -> inside Presentation mode specifically: the dot snaps to
       screen CENTER the instant you start pointing, then hand
       movement from there sweeps the whole screen across a
       virtual box ~4 hand-widths wide (measured from your own
       hand size at that moment) -- same comfortable movement
       works whether you're 1m or 4m from the camera, unlike
       the 1:1 absolute mapping used everywhere else
    -> inside Cursor mode: see MODE: CURSOR above

HAND_LEFT / HAND_RIGHT / HAND_UP / HAND_DOWN (a swipe, started by
closing the fist then opening the palm)
    -> inside Flip mode:
         hand UP    = scrolls to reveal LATER content (drag-up feel)
         hand DOWN  = scrolls to reveal EARLIER content (drag-down feel)
         hand RIGHT = switches to the previous macOS Space/desktop
         hand LEFT  = switches to the next macOS Space/desktop
                       (always switches desktops now -- no more
                        per-app "flip the photo/page instead" case)
       (PINCH is ignored entirely here too -- swiping naturally passes
        through pinch-like hand poses, so detection only ever runs in
        Cursor mode, switched off everywhere else)
    -> inside Quick Command Circle: picks one of the 4 modes below

HAND_LEFT / HAND_RIGHT (closed fist, wrist moved sideways -- no
open-palm arming step needed, unlike the swipe above)
    -> inside Presentation mode only:
         hand RIGHT = next slide
         hand LEFT  = previous slide
       Tracked from the wrist (not the fingertip) and uses its own
       thresholds, tuned independently from the Flip-mode swipe above
       so it can be adjusted for presenting distance (2-4m) without
       affecting Flip mode.

NOTE on scroll direction (Flip mode and Cursor mode): both use
"natural"/drag scrolling, same as a touchscreen or a Mac trackpad with
natural scrolling on -- moving your hand feels like grabbing and
dragging the content itself, not turning an old-style scroll wheel.

Closed_Fist -> Open_Palm (fist closes, then opens)
    -> if no other mode is active: opens the Quick Command Circle

ONE_FINGER / TWO_FINGERS / THREE_FINGERS / FOUR_FINGERS
    -> only detected/published while in Call mode -- see that section
       above. Showing the same finger count in any other mode is
       ignored.


QUICK COMMAND CIRCLE (gesture-only: close fist, then open palm)
-------------------------------------------------------------------
A circle appears on screen with the system's 4 other modes laid out
around it. Swipe in a direction to enter that mode -- the circle closes
automatically. Only opens when you're not already in a mode.

    swipe UP     -> enters Flip mode
    swipe DOWN   -> enters Cursor mode
    swipe LEFT   -> enters Presentation mode
    swipe RIGHT  -> enters Call mode


KEYBOARD
----------
ctrl+shift+p           -> enters Presentation mode
ctrl+shift+f           -> enters Flip mode
ctrl+shift+c           -> enters Cursor mode
ctrl+shift+w           -> enters Call mode
right arrow (no other keys held)  -> next slide (Presentation mode only)
left arrow (no other keys held)   -> previous slide (Presentation mode only)
esc                    -> exits whichever mode is active (any mode, any time)
alt+shift (held)       -> activates the face-gesture layer below (works
                           in ANY mode or no mode at all)

(All four mode combos share ctrl+shift, distinguished by a third key
that's the first letter of the mode: p/f/c/w -- "w" now stands for
Call mode, reusing the old Window Management slot as-is.)

Holding a key down and releasing it are tracked as two separate
moments -- while a key combo is held, other gesture/voice actions can
still fire independently at the same time.


FACE (FaceRecognizer -- always on, no mode required)
--------------------------------------------------------
A second, independent camera-based recognizer (face_landmarker.task)
running in parallel with the hand-gesture pipeline. Publishes its own
signals; nothing here requires being in any particular mode.

    Nod (head pitches down then back up quickly)     -> CONFIRM
    Head tilt left/right (held past ~15 degrees)      -> HEAD_TILT_LEFT
                                                          / HEAD_TILT_RIGHT
    Eyebrows raised / lowered                          -> EYEBROWS_UP /
                                                          EYEBROWS_DOWN
    Mouth opens (rising edge only)                     -> MOUTH_OPEN
    Two blinks within ~0.5s of each other              -> DOUBLE_BLINK
                                                          (a single blink
                                                          fires nothing)

CONFIRM, EYEBROWS_UP/DOWN are published but not wired to any action
yet -- reserved, same status as voice's "yes"/"no". (Shake/CANCEL
existed here previously and has been removed entirely.)

Wired today, ONLY while holding alt+shift (see KEYBOARD above):
    head tilt right  -> next track (system media key)
    head tilt left   -> previous track (system media key)
    mouth open       -> play/pause (same toggle as voice "start"/"stop")
    double blink      -> takes a full-screen screenshot (Cmd+Shift+3)

NOTE on tilt-left vs tilt-right: which physical direction maps to
which label has not been empirically verified against a real camera --
if next/previous come out swapped, flip the sign check in
FaceRecognizer._check_tilt.


SETUP REQUIRED BEFORE THESE WORK
------------------------------------
- Accessibility permission granted to the terminal/app running this
  program -- REQUIRED for basically everything (cursor movement,
  clicks, scrolling, key presses). Without it, these silently do
  nothing with no error message at all. Check the console at startup
  for an "[ACCESSIBILITY WARNING]" banner.
  System Settings -> Privacy & Security -> Accessibility.
- Two Shortcuts authored once in the macOS Shortcuts app, named
  exactly "Enable Do Not Disturb" and "Disable Do Not Disturb"
- Spotify installed (for "study mode" focus music)
- VS Code's "code" command installed on PATH (for "open vscode")
- Microsoft Teams installed, for Call mode's mute/camera/raise-hand
  shortcuts to have anything to act on
